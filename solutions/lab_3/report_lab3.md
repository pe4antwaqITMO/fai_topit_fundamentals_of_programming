## 2. Псевдокод и сложность алгоритмов (Задание 2)

### Псевдокод проверки простоты числа (`is_prime`)
```text
ФУНКЦИЯ is_prime(n):
    ЕСЛИ n < 2 ТО ВЕРНУТЬ Ложь
    ЕСЛИ n == 2 ТО ВЕРНУТЬ Истина
    ЕСЛИ n mod 2 == 0 ТО ВЕРНУТЬ Ложь
    divisor <- 3
    ПОКА divisor * divisor <= n ВЫПОЛНЯТЬ:
        ЕСЛИ n mod divisor == 0 ТО ВЕРНУТЬ Ложь
        divisor <- divisor + 2
    ВЕРНУТЬ Истина
```

### Псевдокод бинарного поиска (`binary_search`)
```text
ФУНКЦИЯ binary_search(sorted_data, target):
    left <- 0
    right <- длина(sorted_data) - 1
    ПОКА left <= right ВЫПОЛНЯТЬ:
        mid <- (left + right) // 2
        ЕСЛИ sorted_data[mid] == target ТО ВЕРНУТЬ mid
        ЕСЛИ sorted_data[mid] < target ТО left <- mid + 1
        ИНАЧЕ right <- mid - 1
    ВЕРНУТЬ -1
```

### Оценка временной и пространственной сложности
* **`analyze_measurements` (два прохода по списку):**
  * Временная сложность: `O(n)`, где `n` — длина списка (выполняются два последовательных линейных прохода).
  * Пространственная сложность: `O(1)` — используются только переменные-аккумуляторы.
* **`linear_search` (линейный поиск):**
  * Временная сложность: `O(n)` в худшем случае, `O(1)` в лучшем.
  * Пространственная сложность: `O(1)`.
* **`is_prime` (проверка простоты):**
  * Временная сложность: `O(sqrt(n))`, где `n` — проверяемое число.
  * Пространственная сложность: `O(1)`.
  * **Обоснование границы `sqrt(n)`:** если составное число `n = a * b`, то оба множителя не могут быть одновременно больше `sqrt(n)`, иначе их произведение превысило бы `n`. Следовательно, хотя бы один делитель не превосходит `sqrt(n)`.
* **`selection_sort` (сортировка выбором):**
  * Временная сложность: `O(n^2)` во всех случаях из-за двух вложенных циклов.
  * Пространственная сложность: `O(n)` на создание копии списка без изменения исходного.
* **`binary_search` (бинарный поиск):**
  * Временная сложность: `O(log n)`, так как на каждом шаге диапазон поиска уменьшается вдвое.
  * Пространственная сложность: `O(1)`.

## 3. Выбор коллекций и сложность операций (Задание 3)

* **Множество (`set`) для хранения уникальных значений:** реализовано на базе хеш-таблицы, что позволяет проверять наличие элемента и добавлять новые записи без дубликатов за `O(1)` в среднем.
* **Кортеж (`tuple`) в качестве ключа словаря:** кортеж неизменяем и хешируем, поэтому его хеш остается постоянным на протяжении всего времени работы программы.
* **Невозможность использования списка (`list`) как ключа:** список является изменяемым типом (`unhashable`). Изменение элементов списка после вставки привело бы к изменению его хеша и нарушению поиска в хеш-таблице.
* **Преимущество словаря (`dict`) перед списком (`list`):** доступ по составному ключу `(student, laboratory)` в словаре выполняется за `O(1)` в среднем, тогда как поиск в списке кортежей требует полного перебора за `O(n)`.

| Коллекция | Средняя сложность добавления | Средняя сложность поиска |
|---|---|---|
| `set` | `O(1)` | `O(1)` |
| `dict` | `O(1)` | `O(1)` |
| `list` | `O(1)` (в конец) | `O(n)` |

## 4. Области видимости LEGB и default-аргументы (Задание 4)

### Схема областей видимости LEGB
```text
+-------------------------------------------------------------------+

| Built-in (B): len(), int(), min()                                 |
|  +-------------------------------------------------------------+  |
|  | Global (G): course = "Программирование на Python"           |  |
|  |  +-------------------------------------------------------+  |  |
|  |  | Enclosing (E): outer_scope_demo -> status             |  |  |
|  |  |  +-------------------------------------------------+  |  |  |
|  |  |  | Local (L): inner_updater -> local_note          |  |  |  |
|  |  |  |            nonlocal status (изменяет E)         |  |  |  |
|  |  |  +-------------------------------------------------+  |  |  |
|  |  +-------------------------------------------------------+  |  |
|  +-------------------------------------------------------------+  |
+-------------------------------------------------------------------+
```

* **Порядок разрешения имен:** `local_note` находится в локальной области **L**; `status` привязывается к объемлющей области **E** с помощью `nonlocal`; `course` ищется по цепочке **L -> E -> G** и находится в глобальной области **G**; встроенная функция `len` проходит **L -> E -> G -> B** и берется из **B**.
* **Ошибка изменяемого значения по умолчанию (`results=[]`):** в Python выражения для значений по умолчанию вычисляются один раз при выполнении инструкции `def`, а не при каждом вызове функции. Созданный список сохраняется в атрибутах объекта функции и переиспользуется во всех последующих вызовах без второго аргумента. Для исправления используется `None` с созданием нового списка внутри функции.
* **Замыкание в `make_threshold_checker(threshold)`:** возвращаемая внутренняя функция `checker` удерживает ссылку на переменную `threshold` из области видимости внешней функции-фабрики после завершения ее выполнения.

## 5. Интеграционное задание: контракты и анализ (Задание 5)

### Контракты публичных функций
1. `mean(values: list[int | float]) -> float`
   * **Вход:** список целых или вещественных чисел.
   * **Выход:** среднее арифметическое элементов.
   * **Особый случай:** при передаче пустого списка возвращает `0.0`.
2. `minimum(values: list[int | float]) -> float | int | None` и `maximum(values: list[int | float]) -> float | int | None`
   * **Вход:** список чисел.
   * **Выход:** минимальное или максимальное значение.
   * **Особый случай:** при пустом списке возвращают `None`.
3. `classify(score: float) -> str`
   * **Вход:** числовой средний балл.
   * **Выход:** строковая категория (`отличный`, `хороший`, `удовлетворительный`, `недостаточный`).
4. `student_summary(name: str, results: list[int]) -> dict[str, object]`
   * **Вход:** имя студента и список его баллов.
   * **Выход:** словарь с полями `name`, `has_results`, `mean`, `min`, `max`, `category`.
   * **Особый случай:** для студента с пустым списком оценок устанавливаются `has_results=False`, `mean=0.0`, `min=None`, `max=None`, `category="нет оценок"`.
5. `find_top_students(students: dict[str, list[int]]) -> list[str]`
   * **Вход:** словарь вида `{имя: [оценки]}`.
   * **Выход:** список имен студентов с максимальным средним баллом (поддерживает несколько лидеров при совпадении балла). Студенты без оценок не учитываются.
6. `group_summary(students: dict[str, list[int]]) -> dict[str, object]`
   * **Вход:** словарь группы.
   * **Выход:** словарь с общим числом студентов, средним баллом по группе, списком лидеров, распределением по категориям и отсортированным рейтингом. Исходный словарь не изменяется.
7. `format_report(student_data: list[dict[str, object]], group_data: dict[str, object]) -> str`
   * **Вход:** список сводок студентов и общая статистика группы.
   * **Выход:** отформатированный текстовый отчет. Для пустой группы возвращает соответствующее уведомление.

### Сложность построения общей статистики
Пусть `N` — количество студентов в группе, `M` — среднее количество оценок у студента:
* Расчет индивидуальных сводок для всех студентов: `O(N * M)`.
* Поиск лидеров группы: `O(N * M)`.
* Сортировка рейтинга студентов методом выбора: `O(N^2)`.
* Итоговая временная сложность: `O(N * M + N^2)`, пространственная сложность: `O(N)` на хранение списка сводок и рейтинга.
